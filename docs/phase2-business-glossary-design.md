# 第二阶段：业务字典与可复用问数

## 目标

让管理员维护团队统一的业务术语、别名和口径说明，并在每次问数时把已启用的字典注入模型上下文。用户不需要记住底层字段名；模型也不会因为同一个词有多种口径而自行猜测。

本阶段随后再增加“收藏问题”和“纠错反馈”。它们复用同一套身份隔离、审计和会话能力，但不与业务字典首个交付耦合。

## 首个交付

- Meta MySQL 新增 `business_glossary` 表：术语、定义、别名、SQL/口径提示、启用状态和更新时间。
- 所有已登录用户可读取已启用字典；仅 `admin` 可创建、修改、启停和删除。
- `GET /api/glossary` 返回启用项；管理接口返回完整列表并可写入。
- QueryService 在图执行前读取启用项，渲染为一个有长度上限、不可执行的纯文本上下文。
- 改写和 SQL 生成提示词都明确：字典用于解释术语，不可覆盖现有行列权限、指标口径、时间范围或 SQL 安全校验。

## 边界

- 字典是全局共享的演示配置，不承载原始业务数据、SQL 模板或用户私密信息。
- 术语与别名不能为空；同一术语唯一；SQL 提示只能是说明文本，不能直接作为可执行 SQL。
- 删除采用物理删除，因为字典不参与历史快照；查询历史仍保存实际执行的结果和 SQL 解释。
- 前端先提供管理员入口和只读列表；收藏与反馈在字典闭环稳定后实现。

## 验收

1. 管理员新增“GMV / 成交总额 / SUM(order_amount)”并启用，普通用户可读取但写入得到 403。
2. 禁用术语后，后续查询上下文不再包含它。
3. 同名术语写入得到 409，不产生重复记录。
4. 字典文本只影响模型理解，不改变 JWT、RLS、掩码、SQL Guard 和标准指标口径的优先级。
